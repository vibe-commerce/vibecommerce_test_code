# Чек-лист одной задачи (готовый для копирования)

Last Updated: 2026-06-02

Скопируй этот чек-лист в свой `backlog/briefs/<date>-<slug>.md` или
`_specs/<feature>/checklist.md` и заполняй галочками по ходу работы.

```markdown
## Чек-лист разработки: <название задачи>

### 1. Идея
- [ ] Идея зафиксирована в `backlog/ideas/<date>-<slug>.md`
- [ ] Идея прожила минимум 1 день и осталась актуальной

### 2. Планирование
- [ ] План написан в файл (`backlog/briefs/` или `_specs/<feature>/`)
- [ ] План содержит: Цель / Контекст / Подход / Альтернативы /
      Риски / Чек-лист / Метрика «успех»
- [ ] Использован скилл `/architect` (если фича сложная)

### 3. Ревью плана
- [ ] План прочитан повторно (через 30+ минут / другим агентом)
- [ ] Цель измерима, чек-лист гранулирован
- [ ] Получено явное «исполняй» (от себя или ревьюера)

### 4. Разработка
- [ ] Изучены 1-2 похожих места в кодбейзе перед написанием нового
- [ ] Чек-лист плана пройден сверху вниз
- [ ] Отклонений от плана нет, ИЛИ они отражены в обновлённом плане
- [ ] Не добавлено лишнего (нет scope creep)

### 5. Feedback Loop
- [ ] `make lint` — зелёный
- [ ] `make test` — зелёный
- [ ] `make test-e2e` (если есть) — зелёный
- [ ] Ни один цикл «фикс → провал» не превысил 3 итерации
      (иначе — пауза, переосмысление подхода)

### 6. Самотестирование (QA)
- [ ] Golden path сценарий проходит
- [ ] Edge cases: пустой ввод / невалидный / race conditions проверены
- [ ] Регрессии: старые фичи не сломались
- [ ] Скилл `/qa-tester` запущен (для UI/веб-проектов)
- [ ] Скрипт `scripts/smoke-test.sh local` (если есть smoke-тесты)

### 7. Документация
- [ ] Скилл `/docs` запущен ИЛИ документация обновлена вручную:
  - [ ] `documentation/<релевантный>.md` (если затронута архитектура /
        тесты / деплой / ошибки)
  - [ ] `_changelogs/CHANGELOG.md` — запись о фиче
  - [ ] `VERSION` — bump по semver (если значимое изменение)
  - [ ] `AGENDA.md` — что сделано в этой сессии
  - [ ] README родительской папки (если добавлены новые файлы)
- [ ] `_specs/<feature>/` — финальное состояние спеки совпадает
      с реализацией

### 8. Push в GitHub
- [ ] `git status` — нет случайных файлов (`.env`, `_private/`)
- [ ] Скилл `/commit` для conventional commit message
- [ ] Скилл `/push` (или `/backup` для commit+push одной командой)
- [ ] Проверка: задача появилась на GitHub

### Готово
- [ ] Все галочки выше = ✅
- [ ] Идея перемещена из `backlog/ideas/` в `_changelogs/` (или
      удалена, если оформилась в спеку)
```

## Правила работы с чек-листом

1. **Не пропускать этапы.** Если этап «не нужен» — обоснуй почему
   в плане. Чаще всего «не нужен» = «не хочется делать», а не
   «правда не нужен».
2. **Помечать сразу.** Не копи галочки на конец дня. Закрыл пункт —
   ✅. Это даёт ощущение прогресса и страхует от пропусков.
3. **Откат разрешён.** Если в этапе 6 нашёл проблему — снимай ✅
   с этапов 5 / 4 и проходи заново. Это лучше, чем фиксить
   полу-сломанное.

## Антипаттерны

❌ **«Разработал → задеплоил → потом задокументирую».** Документация
   после деплоя не пишется.
❌ **«Тесты упали, но фича же работает, я закоммичу».** Тесты
   красные = задача не закрыта.
❌ **«Зачем checklist, я и так помню».** Через 3 этапа что-то
   потеряется.
