# _practices/ — рабочие подходы

Last Updated: 2026-05-01

Папка с **practical workflows** — как именно работать с этим репозиторием
по шагам. В отличие от `documentation/` (факты о реализованном) и
`CLAUDE.md` (инструкции для AI), здесь лежат **практики для человека**:
порядок действий, чек-листы, антипаттерны.

## Содержимое

| Файл | О чём |
|------|------|
| [00-WORKFLOW.md](00-WORKFLOW.md) | **Главный документ.** Полный цикл от идеи до push: 8 этапов |
| [01-plan-then-act.md](01-plan-then-act.md) | Сначала план в файл, согласование, только потом исполнение |
| [02-memory-via-readme.md](02-memory-via-readme.md) | README в каждой подпапке как навигационная память репозитория |
| [03-development-checklist.md](03-development-checklist.md) | Готовый чек-лист для копирования в каждую новую задачу |
| [04-feedback-loop.md](04-feedback-loop.md) | Цикл lint → test → fix → repeat (max 3 итерации) |
| [05-document-and-backup.md](05-document-and-backup.md) | После разработки — документировать, потом push |

## Связь с остальными слоями репо

```
CLAUDE.md (правила для AI)
    │
    ├─→ _practices/ (как ты работаешь по шагам — этот каталог)
    │       │
    │       └─→ ссылается на скиллы (/plan, /test, /docs, /backup)
    │
    ├─→ .claude/rules/ (автоматические триггеры для AI)
    │
    └─→ documentation/ (факты о результате: что есть, что работает)
```

## Когда использовать что

- Новая фича → читай `00-WORKFLOW.md` целиком
- «Что мне сейчас делать?» → возьми `03-development-checklist.md`
  и заполняй галочками по ходу
- Сомневаешься, нужен ли план → читай `01-plan-then-act.md`
- Коллега не понимает структуру репо → отправь
  `02-memory-via-readme.md`
- Прогнал тесты — что дальше → `04-feedback-loop.md` →
  `05-document-and-backup.md`
