# `_private/` — приватная зона

Вся папка `_private/` целиком в `.gitignore`. Здесь лежит то, что **никогда**
не должно попасть в git: credentials, PII, рабочие документы клиентов,
диаризации встреч, инвойсы.

> ⚠️ **Перед `git add` любого файла проверь, что он НЕ внутри `_private/`.**
> Если случайно добавил — `git rm --cached <file>` и проверь, что коммит
> не уехал в remote.

## Что куда класть

### `secrets/` — критичные ключи

**Класть:** `.env.local`, копии production `.env`, ключи API (`.pem`,
`.key`), сервисные аккаунты, токены в plaintext.

**НЕ класть:** обычные документы, расшифровки встреч, инвойсы — для
этого есть `docs/` или `meetings/`.

Проверка перед коммитом: `grep -r "secret\|token\|password" .` не
должен находить ничего ВНЕ `_private/secrets/`.

### `docs/` — рабочие документы с PII

**Класть:** инвойсы, акты, карточки контрагентов, переписка по сделкам,
сканы паспортов / договоров, любые документы с персональными данными.

**НЕ класть:** ключи API (это в `secrets/`), расшифровки встреч (в
`meetings/`).

### `meetings/` — расшифровки встреч

**Класть:** диаризации, расшифровки звонков, протоколы 1-on-1,
заметки стратегических сессий **с упоминанием персоналий**.

**НЕ класть:** обезличенные итоги встреч (они идут в `__STRATEGY_SESSIONS/`
если такая папка есть в проекте).

### `data/` — прочие приватные данные

**Класть:** выгрузки CRM с PII, частные датасеты под NDA,
скриншоты с personal-данными, любые временные приватные данные.

**НЕ класть:** обезличенные датасеты для обучения / эвалов
(они в `_evals/` если такая папка есть).

## Что делать, если случайно закоммитил

1. **Не паникуй** — пока не запушено, можно поправить локально.
2. `git rm --cached <file>` (удаляет из индекса, но не с диска)
3. Закоммить удаление с пометкой `chore: remove accidentally committed
   private file`
4. Если **уже запушено** — нужно переписывать историю (`git filter-branch`
   или `git filter-repo`) и принудительно ротировать секрет, если это был
   credential. Простого удаления недостаточно — секрет уже в публичной
   истории.

## Связь с `.gitignore`

В корневом `.gitignore` должна быть строка:

```
_private/
```

Это закрывает всю папку и все подпапки **рекурсивно** одной записью.

Проверка:

```bash
git check-ignore -v _private/secrets/test.txt
# должно вернуть: .gitignore:N:_private/   _private/secrets/test.txt
```
