## Что здесь

Markdown-файлы с сырыми идеями, гипотезами, заметками. Имя:
`YYYY-MM-DD-<slug>.md`.

## Зачем

Захват идей в момент возникновения, без обязательства превращать
их в задачи. **Промежуточный буфер** между мыслью и формальным брифом.

Жизненный цикл идеи (со 0.5.0):
```
ideas/ → briefs/ (стоит ли?) → plans/ (как?) → код → documentation/
            │                       │
            ↓                       ↓
   archive/rejected/          archive/done/
```

Главный вопрос идеи: **«А что если?»**. Не нужно сразу определять scope,
acceptance criteria, шаги — это в брифе и плане соответственно.

## Как пользоваться

- **Создание:** один файл = одна идея. Дата в имени = дата возникновения.
- **Структура файла:** заголовок, контекст, гипотеза, связанные источники.
  Шаблон:
  ```markdown
  # <название идеи>
  Дата: YYYY-MM-DD
  Автор: …
  Статус: идея → бриф → план → … (обновляй по мере жизни)

  ## Контекст
  ## Гипотеза / суть
  ## Зачем сейчас
  ## Связанные источники
  ```
- **Промоут в бриф:** перенос в `../briefs/<slug>.md` с расширенной
  структурой по шаблону [`../../_specs/templates/brief.md`](../../_specs/templates/brief.md).
  Удалить из `ideas/` после промоута (или перенести в `archive/done/` —
  если идея ценна как пример).
- **Промоут сразу в план:** для лёгких фич (≤1 день) допустимо сразу
  в `../plans/<slug>.md` по шаблону [`../../_specs/templates/plan.md`](../../_specs/templates/plan.md),
  минуя бриф.
- **Удаление / архивация:** идею можно удалить если устарела или решена
  в коде; если отказались сознательно — перенести в
  `../archive/rejected/<slug>.md` с секцией «Почему отказались»
  (по шаблону `_specs/templates/rejected.md`).
