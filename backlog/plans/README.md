# `backlog/plans/` — планы реализации

Last Updated: 2026-06-02

## Что здесь

Markdown-файлы с **планами реализации** уже согласованных идей и
брифов. Имя: `YYYY-MM-DD-<slug>.md`.

Plan отвечает на вопрос **«как делать?»**:

- Какой подход выбрали и почему?
- Какие альтернативы отвергли?
- Какие риски и митигации?
- Чек-лист задач для исполнения.
- Метрика «успех».

В отличие от **brief** (про «зачем / стоит ли делать?») — план
про **исполнение**.

## Зачем отдельная папка

Brief смешивался с планом — это размывало семантику и приводило
к гибридным «брифам-планам». Теперь чётко разделено:

| Слой | Главный вопрос |
|------|----------------|
| `ideas/` | «А что если?» |
| `briefs/` | «Стоит ли делать?» (приоритизация) |
| `plans/` | «Как делать?» (исполнение) |

## Жизненный цикл

```
ideas/  →  briefs/  →  plans/  →  код  →  documentation/
                          ↓
                  archive/done/      (после реализации)
                  archive/rejected/  (если отказались на этапе плана)
```

Лёгкая фича (≤1 день) — допустимо пропустить `briefs/` и сразу писать
в `plans/`. Бриф без плана — нормально (фича в очереди приоритизации).
Плана без брифа быть не должно для крупных фич — иначе риск делать «не то».

## Как пользоваться

- **Создание:** перенос из `../briefs/<slug>.md` (или сразу из `ideas/`,
  если фича лёгкая) с расширенной структурой по шаблону
  [`../../_specs/templates/plan.md`](../../_specs/templates/plan.md).
- **Согласование:** план НЕ исполняется до явного сигнала
  «делай» / «ок» / «поехали» (см.
  [`../../.claude/rules/plan-before-act.md`](../../.claude/rules/plan-before-act.md)).
- **Промоут в `_specs/`:** только если фича крупная (>3 дней) и нужны
  tech-spec / user-spec / ADR. План остаётся в `plans/`, а в
  `_specs/<feature>/` живут спецификации архитектуры.
- **После реализации:** перенос в `archive/done/<slug>.md`.
- **При отказе:** перенос в `archive/rejected/<slug>.md` с обязательной
  секцией «Почему отказались».
