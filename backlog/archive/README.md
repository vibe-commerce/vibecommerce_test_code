# `backlog/archive/` — архив исходов идей и брифов

Last Updated: 2026-05-02

## Что здесь

Архив разделён по **исходу** документа:

| Подпапка | Что содержит | Когда переносить |
|----------|--------------|------------------|
| [`done/`](done/README.md) | Реализованные брифы и планы | После полной реализации + changelog |
| [`rejected/`](rejected/README.md) | Отказанные идеи, брифы, планы | Сразу после решения «не делаем» (с обязательным «Почему») |

## Зачем разделять

Раньше архив был один — и туда уезжали только реализованные документы,
а отказанные предлагалось удалять. На практике «почему мы отказались
от X» часто полезнее, чем «что мы сделали»: защита от повторного захода,
контекст для новых форкеров, триггеры пересмотра.

См. историю рефакторинга lifecycle в [`../../_changelogs/CHANGELOG.md`](../../_changelogs/CHANGELOG.md).

## Содержимое верхнего уровня (исторические артефакты)

Файлы, попавшие в архив до lifecycle-рефактора (0.5.0):

| Файл | Назначение |
|------|------------|
| `starter-repo-improvements.md` | План апгрейда v0.0.2 → 0.2.x (реализован) |
| `starter-repo-improvements-all-details.md` | Companion к плану выше (готовые реализации) |
| `external-insights.md` | 14 community-инсайтов (интегрированы в `90-AI-AGENT-BEST-PRACTICES.md`) |
| `briefs/` | Реализованные брифы до 0.5.0 (плоская папка, не разделённая по исходу) |
| `ideas/` | Реализованные идеи до 0.5.0 |

После 0.5.0 новые архивные документы кладутся **только** в `done/` или
`rejected/`. Старая плоская структура `archive/briefs/`, `archive/ideas/`
сохраняется как есть — миграция отложена (D6 рефактор-плана).
