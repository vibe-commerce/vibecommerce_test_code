# `_reports/` — периодические отчёты

Last Updated: 2026-05-01

## Что здесь

Готовые / в работе отчёты:
- Weekly / monthly review проекта
- Release-summary после крупных деплоев
- Аудиты (security, perf, costs)
- Постмортемы инцидентов

Имя файла: `YYYY-MM-DD-<тип>.md`. Пример: `2026-04-01-monthly.md`,
`2026-03-15-release-v1.2.md`, `2026-02-20-postmortem-db-outage.md`.

Сейчас папка пустая — наполняется по мере работы.

## Зачем

Чтобы периодические отчёты не плодились по всему репо в случайных местах.
Все «оглядки назад» (review / postmortem / audit) — здесь.

Отличие от `_status/`:
- `_status/` = снимок «что СЕЙЧАС работает»
- `_reports/` = срез «что было ЗА период» / «после события»

## Как пользоваться

- **Создание отчёта:** один файл = один отчёт. Дата в имени.
- **Структура:** заголовок + период + summary + детали по разделам.
  Шаблон зависит от типа (weekly иначе чем postmortem).
- **Архивация:** не удаляй старые отчёты — они контекст для будущих
  решений. Если разрослось — раз в год переноси в `_reports/archive/`.
